# Раздел «Модерация каналов»

## Цель

Добавить отдельный раздел, в котором бессрочно хранится и отображается история Telegram-каналов и групп, куда хотя бы один аккаунт подал заявку на вступление. Пользователь должен видеть, какие заявки ещё ожидают решения, какие аккаунты уже вступили и сколько заняло ожидание.

## Границы

- Раздел объединяет каналы из каталогов `outbound` и `scout`.
- В список попадают только каналы, для которых хотя бы одна membership-запись когда-либо получила статус `pending_approval`.
- Успешно завершённые заявки не удаляются и остаются в истории бессрочно.
- Раздел читает локальную SQLite-базу и сам не выполняет Telegram-запросы.
- Текущие Telegram listener, trigger, round-robin и отправка сообщений не изменяются.
- Во время разработки Telegram-процессы и боты не запускаются.

## Модель данных

Существующая таблица `account_channel_memberships` остаётся источником истины. В неё добавляются поля:

- `request_submitted_at` — UTC-время успешной подачи заявки;
- `joined_at` — UTC-время, когда периодическая проверка впервые подтвердила вступление.

Правила записи:

- при переходе `joining -> pending_approval` заполняется `request_submitted_at`, если поле ещё пустое;
- повторные проверки не изменяют исходное время подачи заявки;
- при переходе `pending_approval -> member` заполняется `joined_at`;
- обычное вступление без модерации не заполняет `request_submitted_at` и не появляется в этом разделе;
- повторная активация канала не уничтожает исторические timestamps успешной заявки;
- длительность ожидания равна `joined_at - request_submitted_at`; для ожидающей заявки — текущее время минус `request_submitted_at`.

Миграция переносит существующие заявки `pending_approval`: если точное время подачи ранее не хранилось, `request_submitted_at` заполняется из `last_check_at`. Это явно считается приблизительным временем. Существующие записи `member` без доказательства прохождения модерации в историю не добавляются.

## Backend API

Wails binding `GetChannelModeration()` возвращает агрегированный список каналов.

Канал содержит:

- ID и каталог;
- заголовок, ссылку и тематику;
- общее число поданных заявок;
- число вступивших аккаунтов;
- число ожидающих аккаунтов;
- агрегированный статус;
- время первой поданной заявки;
- длительность ожидания;
- вложенный список аккаунтов.

Аккаунт содержит:

- ID и безопасное отображаемое имя/маскированный телефон;
- роль;
- время подачи заявки;
- время вступления;
- длительность ожидания;
- фактический статус `pending_approval`, `member`, `error` или `flood_wait`.

Telegram ID пользователя и иные личные данные в DTO не передаются.

## Агрегированные статусы

- `pending_approval` / «Ожидание модерации» — ни один аккаунт ещё не вступил, есть ожидающие;
- `partial` / «Частично» — часть аккаунтов вступила, часть ожидает;
- `member` / «Успешное вступление» — все аккаунты, подавшие заявку, вступили.

Membership со статусами `error` и `flood_wait`, если у неё есть `request_submitted_at`, остаётся в истории. Она учитывается как ожидающая, а в детализации показывает свой фактический статус и ошибку без секретов.

Для строки канала «Первая заявка» равна минимальному `request_submitted_at`. Пока есть ожидающие, общая длительность считается от первой заявки до текущего времени. Когда все вступили, длительность считается от первой заявки до последнего `joined_at`.

## Интерфейс

В боковом меню появляется пункт «Модерация каналов» после раздела «Каналы».

Верхняя строка содержит:

- поиск по названию, ссылке и тематике;
- фильтр `Все / Ожидают / Частично / Вступили`;
- счётчики каналов и заявок;
- время последнего локального обновления.

Основная таблица:

`Канал | Тематика | Заявок | Вступили | Ожидают | Статус | Первая заявка | Время ожидания`

Строка раскрывается и показывает таблицу аккаунтов:

`Telegram-аккаунт | Роль | Заявка подана | Вступил | Через сколько | Статус`

UI обновляет данные из локальной БД раз в 15 секунд и при открытии раздела. Состояние раскрытых строк сохраняется при фоновом обновлении. Пустой список показывает спокойное сообщение «Заявок на модерацию пока нет».

## Адаптивность

- Страница не создаёт общий вертикальный скролл приложения; прокручивается только область таблицы.
- На узком окне второстепенные колонки скрываются через существующее меню видимости столбцов.
- Таблица использует общий компонент настроек колонок: порядок, ширина, видимость и сортировка сохраняются локально отдельно для этого раздела.
- Светлая тема остаётся темой по умолчанию; тёмная использует текущие системные токены приложения.

## Ошибки и обновление

- Ошибка чтения БД показывается внутри раздела и не останавливает приложение.
- Последние успешно загруженные данные остаются видимыми при временной ошибке обновления.
- Фоновый таймер останавливается при уходе со страницы.
- Формат времени в интерфейсе: `ДД.ММ.ГГГГ | ЧЧ:ММ`, локальная зона приложения.
- Длительность отображается компактно: `12 мин.`, `3 ч. 18 мин.`, `2 д. 4 ч.`.

## Проверка

- Миграционный тест подтверждает сохранение старых membership-записей и новых timestamps.
- Unit-тесты проверяют фиксацию подачи заявки и вступления без перезаписи timestamps.
- Wails-тесты проверяют выбор только каналов с заявками и агрегацию трёх статусов.
- Frontend-тесты проверяют поиск, фильтры, раскрытие, формат длительности и обновление без Telegram-вызовов.
- Полная проверка выполняется офлайн: `go test ./...`, frontend tests и production build.
