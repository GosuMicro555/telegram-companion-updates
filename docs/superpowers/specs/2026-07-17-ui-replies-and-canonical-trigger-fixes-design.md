# Исправления UI, раздельные ответы и канонические триггеры

**Дата:** 17.07.2026  
**Версия приложения:** без изменения, `0.5.0`

## Цель

Исправить обнаруженные дефекты статистики и аналитики, разделить тексты ответов для комментариев и личных сообщений и восстановить гарантированное срабатывание активных канонических триггеров вместе со всеми привязанными формами.

## Объём работ

### Общий выбор даты и времени

- Нативные `datetime-local` заменяются общим лёгким компонентом для «Статистики аккаунтов» и «Live-статистики».
- Компонент содержит навигацию по месяцам, календарную сетку, выбор часов и минут, действия «Применить» и «Очистить».
- Внешнее значение остаётся в формате `YYYY-MM-DDTHH:mm`, поэтому существующий API фильтрации не меняется.
- Поповер закрывается по `Escape`, клику снаружи и после применения значения.
- Светлая и тёмная темы используют существующие CSS-переменные приложения; новые зависимости не добавляются.

### Меню столбцов

- Общий компонент таблиц корректно скрывает меню через атрибут `hidden`.
- Клик снаружи и `Escape` закрывают меню в обеих статистиках.
- Порядок, ширина и видимость столбцов продолжают сохраняться раздельно для каждой таблицы.

### Типографика и следующий сбор

- На странице «Обновления» удаляются локальные переопределения шрифта, из-за которых она отличается от прежнего вида приложения.
- Если следующий автоматический сбор не назначен, выводится `—`; отображение даты последнего сбора не меняется.

### Удаление триггера из Live-статистики

- Удаление выполняется в backend как единая операция над активным каноническим триггером.
- После успеха интерфейс повторно загружает сохранённые настройки keyword и синхронно обновляет «Позитивные» и «Ключевые слова».
- Локальный устаревший список не должен возвращать удалённый триггер при следующем автосохранении.

### Раздельные тексты ответов

В разделе «Ключевые слова» отображаются две компактные строки:

1. «Единый ответ в комментариях».
2. «Единый ответ в ЛС».

Оба значения:

- сохраняются локально и восстанавливаются после перезапуска;
- публикуются в runtime-конфигурацию без `STOP/START`;
- могут отличаться друг от друга;
- сохраняют введённые пробелы и переносы по действующему контракту настроек.

При отправке:

- ответ в обсуждении использует публичный текст;
- личное сообщение использует текст для ЛС;
- если ЛС закрыта и доставка переключается на ответ в обсуждении, используется публичный текст;
- пустое поле соответствующего типа приостанавливает только этот тип отправки и не останавливает listener.

Для обратной совместимости при первом чтении старых настроек отсутствующее поле ответа в ЛС получает текущее значение публичного ответа. После первого сохранения оба поля становятся независимыми.

### Канонические триггеры

Активный позитивный канон `тест` должен срабатывать на:

- сам канон `тест`;
- каждую связанную форму, включая `тестик`;
- только отдельное нормализованное слово, без ложного совпадения по подстроке.

Исправление проверяет всю цепочку:

1. `trigger_active` и класс канона в SQLite.
2. Загрузка канона и форм из `canonical_keyword_forms`.
3. Публикация всех форм в `runtimeconfig.CanonicalTriggers`.
4. Нормализация входящего сообщения и поиск совпадения.
5. Наличие активного исходящего канала.
6. Постановка задания и выбор подходящего аккаунта-спамера.
7. Выбор публичного или личного текста непосредственно перед отправкой.

Исправление должно устранять найденную первопричину, а не добавлять отдельное исключение для слов `тест` и `тестик`.

## Данные и совместимость

- В `KeywordSettings`, Wails DTO и runtime snapshot добавляется независимый ответ для ЛС.
- Текущие аккаунты, tdata-сессии, роли, каналы, прокси, keyword и статистика сохраняются.
- Новая версия приложения и новая запись release notes не создаются.
- Миграция БД не требуется: настройки хранятся в JSON и новое поле обратно совместимо.

## Проверка

- Компонентные тесты общего календаря и закрытия меню.
- Тест синхронизации keyword после удаления из Live-статистики.
- Backend-тест сохранения и горячей публикации двух ответов.
- Тест outbound: комментарий, ЛС и fallback используют правильный текст.
- Сквозной тест канона с формами `тест` и `тестик` до постановки задания.
- Тест пустого значения «Следующий сбор» (`—`).
- Полный frontend и Go test suite, Wails-сборка и запуск установленного приложения в Ubuntu.
