# Проектирование Live-статистики доставки

## Цель

Добавить отдельный основной раздел `Live-статистика`. Он показывает окончательный результат каждой отправки, вызванной ключевым словом, не меняя работающую логику Telegram-доставки, повторных попыток, лимитов, round-robin и чередования ЛС с ответами. Существующий раздел `Статистика` переименовывается в `Статистика аккаунтов`.

## Утверждённое поведение

- В столбце `Сообщение` отображается исходное сообщение, вызвавшее триггер.
- Текст хранится локально и бессрочно.
- Имя автора, его Telegram ID и другие идентифицирующие сведения в Live-истории не сохраняются.
- Время срабатывания фиксируется, когда приложение определило необходимость ответа.
- Строка становится видимой только после окончательного результата: `Успешно` или `Не доставлено`.
- Промежуточного статуса в базе и интерфейсе нет.
- Если ЛС закрыты, но последующий ответ в комментариях успешен, строка отображается как `Ответ / Успешно`. Существующий агрегированный счётчик закрытых ЛС продолжает работать отдельно.
- Во вкладке отображается размер SQLite-базы в МБ с учётом основного файла и активного WAL-файла.

## Архитектура

Используется отдельная таблица `live_delivery_history`. Экран не строится напрямую из технических записей очереди и событий. Очередь остаётся источником истины для доставки и повторных попыток, а Live-история является отдельной аудиторской проекцией со своим репозиторием и Wails API.

Запись истории содержит:

- стабильный ID и уникальный ID исходящей задачи;
- обезличенный исходный текст сообщения;
- ID канонического ключа, пока канон существует;
- неизменяемый снимок текста канона;
- время срабатывания триггера в UTC;
- итоговый тип доставки: `private_message` или `public_reply`; если отправка ни разу не началась, интерфейс показывает `—`;
- итоговый ID аккаунта и неизменяемый снимок его отображаемого имени; если задача завершилась до назначения аккаунта, оба значения остаются пустыми и интерфейс показывает `—`;
- итоговый статус: `successful` или `not_delivered`;
- технический код ошибки для диагностики;
- время завершения доставки.

Индексы создаются по времени срабатывания, статусу, ID канона и стабильному обратному порядку `(triggered_at, id)`.

## Поток данных

1. При совпадении ключа исходящая задача и скрытая запись аудита создаются в одной транзакции. Сохраняются исходный текст, снимок канона и время срабатывания.
2. Существующие планировщик, выбор аккаунта, повторы, чередование ЛС и ответа, rate limit, FloodWait и маршрутизация через прокси продолжают работать без изменений.
3. Успешная отправка финализирует запись фактическим аккаунтом и фактическим типом доставки.
4. Восьмая неудачная попытка, после которой задача сейчас уходит в dead letter, финализирует запись как `not_delivered`.
5. Live API возвращает только финализированные строки.
6. Закрытая личка с последующим ответом в комментариях финализируется один раз как успешный публичный ответ.

Операции аудита идемпотентны по ID исходящей задачи. Повторная фиксация результата не создаёт и не учитывает вторую строку.

## API выборки

Добавляется постраничный запрос Live-статистики со следующими параметрами:

- дата и время `с` и `по`;
- номер страницы;
- размер страницы: только `50`, `100`, `200`, `500` или `1000`;
- поддерживаемый столбец и направление сортировки;
- общее количество подходящих строк;
- размер SQLite-базы в байтах для точного преобразования в интерфейсе;
- время последнего обновления.

Дата и время из интерфейса интерпретируются в локальном часовом поясе и преобразуются в UTC на границе Wails. Русский интерфейс отображает время срабатывания по Москве.

## Интерфейс

В основном боковом меню:

- существующий пункт `Статистика` переименовывается в `Статистика аккаунтов`;
- сразу под ним добавляется самостоятельный пункт `Live-статистика`;
- экран `Статистика аккаунтов` сохраняет существующую агрегированную статистику;
- экран `Live-статистика` содержит новую таблицу аудита.

В компактной верхней панели Live-экрана находятся поля даты и времени `С` и `По`, количество найденных строк, размер базы в МБ и время последнего обновления.

Столбцы таблицы:

`Сообщение | Триггер | Тип | Дата | Время | Telegram-аккаунт | Статус`

По умолчанию новые строки находятся сверху. Типы отображаются как `ЛС` и `Ответ`, статусы — зелёный `Успешно` и красный `Не доставлено`. Дата и время находятся в отдельных столбцах и используют русский формат в русской локали.

В ячейке триггера находится компактный крестик. Он без подтверждения удаляет канон целиком из `Позитивных` и активных `Ключевых слов`. Исторические строки сохраняют снимок триггера и показывают, что канон удалён.

Размер страницы выбирается из `50`, `100`, `200`, `500`, `1000`; значение по умолчанию — `50`. Пагинация, фильтрация и сортировка выполняются в SQLite, а не над всей историей во frontend.

## Единый компонент таблиц

Существующее поведение настраиваемых таблиц выделяется в один переиспользуемый компонент для обеих таблиц статистики. Он предоставляет:

- изменение порядка столбцов перетаскиванием;
- изменение ширины с минимальными ограничениями;
- скрытие и возврат столбцов;
- сортировку кликом по заголовку;
- раздельное сохранение порядка, ширины и видимости для каждой таблицы после перезапуска.

У Live-таблицы отдельный ключ настроек, поэтому её конфигурация не меняет таблицу `Статистика аккаунтов`. Изменения общего поведения и стилей компонента применяются к обеим таблицам.

Вертикально прокручивается только тело таблицы; вся страница приложения остаётся внутри окна без общего вертикального скролла.

## Обновление и нагрузка

Live-страница обновляется раз в пять секунд только тогда, когда раздел открыт и документ видим. Опрос останавливается при переходе в другой раздел, сворачивании приложения или закрытии представления. Каждый запрос загружает только активную отфильтрованную страницу и количество строк, но не всю историю.

Ошибка обновления показывается неблокирующей строкой, при этом последняя успешно загруженная страница остаётся видимой. Telegram-доставка не зависит от открытого интерфейса или работающего опроса.

## Тестирование

Через TDD покрываются:

- транзакционное создание задачи и аудита;
- отсутствие идентификаторов автора в сохранённой истории;
- успешная финализация ЛС и публичного ответа;
- закрытая личка с успешной заменой на ответ;
- окончательная ошибка после исчерпания повторов;
- идемпотентная повторная финализация;
- фильтры даты и времени, сортировка, количество строк и все размеры страниц;
- расчёт размера базы с учётом WAL;
- удаление канона из позитивных и активных триггеров с сохранением истории;
- запуск и остановка опроса в зависимости от открытого раздела;
- независимое сохранение порядка, ширины и видимости столбцов;
- скролл таблицы без вертикального скролла всей страницы.

Существующие тесты совпадения триггеров, динамического единого ответа, чередования доставки, агрегированной статистики и прокси-маршрутов остаются обязательными регрессионными проверками.
