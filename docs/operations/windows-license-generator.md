# Windows-генератор лицензий

Внутренний `Telegram Companion License Generator.exe` работает только на доверенном Windows-компьютере владельца лицензий. Он не входит в `.dmg`, Sparkle-архив или release-only GitHub repo.

## Правила хранения ключа

- Лицензии подписываются отдельным Ed25519 license key. Этот ключ не используется для подписи `.app` или Sparkle updates.
- Private key хранится только локально в состоянии генератора и защищён Windows DPAPI. В приложение macOS встраивается только public key.
- Переносимая резервная копия private key должна быть зашифрована паролем и аутентифицированным шифрованием. Храните её отдельно от компьютера, но не расшифрованную копию.
- Private key, расшифрованная резервная копия, license tokens и секреты не должны попадать в Git, сборочные артефакты, GitHub Releases, логи или историю выдачи.

## Выпуск лицензии

1. На Mac откройте экран активации и получите производный `Machine ID`. Исходный `IOPlatformUUID` не запрашивайте и не записывайте.
2. На Windows откройте генератор, введите `Machine ID`, имя владельца и при необходимости комментарий. Срок действия оставьте пустым, если нужна бессрочная лицензия.
3. Перед выпуском проверьте фиксированные значения продукта `telegram-companion` и канала `public-macos-arm64`. Генератор не должен выпускать ключ для другого продукта или канала.
4. Выпустите подписанный текстовый ключ и, при необходимости, экспортируйте эквивалентный файл `.tcomplicense`.
5. Передайте ключ пользователю напрямую согласованным защищённым способом. Не сохраняйте его в GitHub, issue, чате проекта или логах.
6. Убедитесь, что локальная история содержит только служебные сведения о выпуске и не содержит private key или полный license token.

## Резервирование и восстановление

1. После первичной настройки создайте зашифрованную переносимую резервную копию private key с уникальным паролем не короче 12 символов и проверьте её восстановление на том же доверенном Windows-профиле.
2. Для восстановления выберите файл резервной копии, введите пароль и подтвердите, что генератор снова видит public key и может выпустить тестовую лицензию.
3. Не удаляйте рабочее состояние до успешной проверки резервной копии. Не переносите DPAPI-защищённое состояние на другой профиль как замену штатному restore.
4. Потеря private key и резервной копии останавливает выпуск новых лицензий, но не отзывает уже выданные офлайн-лицензии. При ротации выпустите новую публичную сборку с новым public key по отдельной процедуре.

## Перед передачей генератора

- Соберите Windows-генератор отдельно от публичной macOS-сборки.
- Проверьте, что в `.exe` нет private key, license token, расшифрованной резервной копии или секретов.
- Храните только DPAPI-защищённое локальное состояние и зашифрованную резервную копию; исходный private key не копируйте в проект.
